# Train Offline V18：先修复经验的证据链，再验证进化收益

更新日期：2026-09-08。本文只制定方案，不实施训练代码修改。

## 1. 结论与本轮边界

V17 已经能生成 Skill 和 Memory，但还没有建立可靠的经验质量与收益证据链。最需要修复的不是经验数量，而是三个具体问题：

1. **标准答案进入过程反思，后续审核又只检查 finding，导致答案信息和错误归因被包装成经验。**
2. **Skill 的跨样本支持不成立，适用条件和行动指令缺少约束，容易生成错误泛化或额外搜索要求。**
3. **Memory 仍大量保存答题复盘、选项对应和过程建议，事实内容与检索问题不匹配。**

效果判断还存在一个必须先解决的实验问题：评测使用 temperature=1.0，相同初始消息的样本也出现大量不同答案。不能把 V17 的组间差值全部解释为经验的作用。

首轮只做三块训练改动：证据隔离与溯源、Skill 合成约束、Memory 事实化。保留当前单次离线反思、分块合成、现有审核、一次提交 final 的流程。不增加自动调参、多智能体批评、候选搜索平台、逐题在线反思或数据库迁移。收益验证放在独立实验流程中，不把完整验证与版本择优系统塞进 `EvolutionPipeline`。

本轮成功标准分两层：工程上阻断下文已确认的失效案例；科研上在未参与经验生成的开发集得到可重复的收益，再在冻结测试集确认。经验变少、审核通过或某次答对题数增加，都不能单独算进化有效。

## 4. 实际学到了什么

### 4.1 数量与筛选

| 数据集 | 有效训练样本 | 选中 bad / good / uncertain | finding | 新 Skill | Memory 候选 / 实际入库 |
| --- | ---: | --- | ---: | ---: | ---: |
| EgoLife | 81 | 43 / 19 / 0 | 62 | 1 | 25 / 25 |
| LVBench | 247 | 147 / 63 / 0 | 210 | 8 | 118 / 118 |
| MedVidBench | 1007 | 880 / 125 / 2 | 1007 | 11 | 561 / 560 |

来源为各目录 `offline_result.json` 和 `reflection/selection.json`。模型权重不训练，执行超参数不变。这里只统计本轮新增经验，不把初始人工 Skill 当成训练学到的规则。

`max_samples=0` 保留全部错题再配正确题，不保证一定达到 7:3。MedVidBench 的最终 bad 比例为 87.39%，可用正确样本不足。903 条样本经过 LLM 结果分类，得到 796 bad、105 good、2 uncertain。这个分类与正式多任务评测分数不是同一量，不能把 880/1007 直接称为官方错误率。

### 4.2 Skill 内容

- **EgoLife：**只有 EntityLog 一条，要求物体移动后结合时间和选项确定移动者。支持样本 16 是拼图板消失与人物推断，226 是 POV 持刀者识别。两条 finding 没有共同展示完整的“移动时间对应责任人”机制。
- **LVBench：**8 条分布在 entity recognition、event understanding、key information retrieval、summarization、temporal grounding，reasoning 没有新增技能。有明确检查事件顺序的规则，也有泛化的多取证建议，以及“忽略顺序逻辑、选最清晰实例”的危险规则。
- **MedVidBench：**11 条分布在八类任务，多数是再看细节、扩大检索、避免猜测。STG 提出 pixel-level extraction，DVC 在预算失败后要求扩大 clip_skim 范围，TAL 要求多个工具取得共识。这些不是已经证明有效的执行策略。

### 4.3 Memory 内容

EgoLife 25 条、LVBench 118 条、MedVidBench 561 条候选全部有非空 lesson 或 pitfall。大量内容仍是“Agent 犯了什么错、下次应如何做”，并非能够直接复用的观测事实。

用 `agent / tool / clip_skim / frame_inspect / failed` 对 context 作简单大小写不敏感检索，命中 9/25、30/118、305/561。此统计只是过程措辞的诊断代理，不等于逐条语义判废数量。

实际检索覆盖差异很大：EgoLife 11/19，LVBench 6/63，MedVidBench 当前 163/163。不能统一归因于记忆太多或阈值太高。`memory_embedding_text()` 拼接 context、evidence、lesson、pitfall、failure_type，而查询是当前视频问题，过程措辞确有稀释检索情境的机制，但尚无消融证明它解释了全部低命中。

## 5. 最典型的问题与证据链

### 5.1 标准答案信息穿过 finding，换一种表述后进入 Memory

**直接案例：M，训练样本 2165。**

`reflection/group_184.json` 的 finding 明确写：预测框 x 起点 306，ground truth 起点 1045，继而推测 Agent 认错了自己的手。后续 Memory 改写成 “the correct location starts at 1045”，保留了坐标和推测。`reflection/memories/audit/grounding_2ff1c45193a44b66f24d1db3.json` 返回 `OK`。

这证明答案来源信息经过措辞转换进入了长期经验，不能证明 1045 是 Agent 当时观察到的坐标。1045 即使数值正确，也不应由标准答案充当观测来源。

**相同链条：E，训练样本 366。**

`reflection/group_001.json` 与最终 Memory 保留 DAY5、118046.7s、“The afternoon before yesterday”(D)、“Yesterday afternoon”(B) 的答案映射。审核 `grounding_b497adac6bb1237a1f253c6a.json` 为 OK。该记忆被注入测试样本 406 的 Shure 喝咖啡问题，但不提供喝咖啡事件本身。406 虽然从错变对，也不能据此证明该记忆提供了正确事实。

根因在代码中是闭合的：

1. `_items()` 把 ground_truth 和轨迹一起准备，`analyze_offline_group()` 只排除 `_` 前缀字段，所以 ground_truth 进入 finding 生成输入。
2. `audit_memory()` 只拿 candidate 和 finding，不读取源轨迹。`audit_skills()` 也只审核清洗过的 findings。
3. 文本校验能拦部分关键词，无法识别“ground truth”被改成“correct location”。Memory 的 `allow_facts=True` 又会跳过源事实重叠检查，这是允许真实事实的必要能力，不能靠重新禁止所有数字或人名修复。

应修复来源隔离与审核输入，而不是继续扩充敏感词列表。

### 5.2 Skill 把相同错误标签当成相同机制

**直接案例：L，样本 4454 与 4731。**

两条 finding 都在 `reflection/group_049.json`。4454 是识别第二位选手的上衣颜色，4731 是通过标题和视觉线索识别盒子内容。它们分别涉及目标顺序与文字线索，却共同支持两条 entity recognition Skill：

- `c808bf116bc1`：优先最清晰实例，忽略 sequence logic。
- `125f9be137b2`：借助标题或字幕解决模糊识别。

审核 `skills/audit/9093fc8a38f32d63/001.json` 与 `6d9112b68db7bc56/001.json` 都接受两个支持样本。4454 的 finding 没有显示被忽略的标题或字幕，4731 也没有展示顺序辨认机制。审核理由对源 finding 作了过度概括。

尤其是第二位、首次、最后一次等限定决定目标身份。“最清晰实例”不能替代目标限定。问题是错误规则本身，不只是 instruction 写得不够具体。

**另一例：L，temporal grounding。**

一条规则混入换人方向、食物和角色，来源分别是浇花、采访人名、吃东西、咖啡店招牌和球员替换。applies_when 直接是 `reasoning / entity recognition / event understanding`。这是按任务标签拼接例子，没有给出新问题中可观察、可执行的触发条件。

**EgoLife 的唯一 Skill 同样需要重审。** 两个 sample ID 只证明数量达到阈值，并不证明同一完整规则被两个样本支持。

### 5.3 生成了更多取证要求，却没有证明何时值得继续

M 的 DVC Skill 引用 4255、2923。前者 finding 包含 frame_inspect 参数错误，后者强调避免重复调用；最终规则却要求在预算失败后扩大 clip_skim 时间范围。两者不共同支持“扩大范围就能解决”的结论，且预算已经耗尽时不能继续执行。

M 的 STG 要求 pixel-level extraction，既没有落到实际参数，也没有证明增加这一表述能改善定位。不能把无法由当前工具执行的能力写成 Skill。

L Skill 组达到步数上限的题从 20/63 增至 33/63，平均 Token 增加 27.95%。这与额外取证负担一致，但同时存在生成波动和非法工具调用，尚不能断言全部成本增量由某条 Skill 引起。V18 应用定向消融检验，不直接扩大预算。

### 5.4 Memory 同时混入事实、选项和策略，命中不等于有用

- E 样本 41 的 Memory 宣扬 extensive search 可以成功，证据只复述选中了“About four hours ago”。它被注入测试 421 的古牌坊经过时间问题，不能提供该事件时间。
- L 测试 3791 问上半场比分，却注入训练 3930 的林丹第二局首分和 4092 的樊振东得分记忆；4178 问第二局某一分前哪支队领先，也命中 3930。二者均从对变错，体现了语义相似但事件不适用的风险，仍需删除注入后的配对重跑才能确认因果。
- M 样本 2923 只有步数耗尽和重复调用经验，仍进入 Memory；审核 `grounding_43d32bd4ec1995b2c6febc67.json` 为 OK。这更适合进入候选过程诊断，不能充当新的医学视频事实。
- M 样本 5601 被解释为 8 轮、50,751 Token 超预算，但 finding 没有证明该任务规定了更低预算。它又变成过程型 Memory。成本高、答错和预算耗尽不是同一个概念。

Memory 事实化预计能减少复盘噪声，但**事实真实也不保证能跨视频迁移**。当前没有结构化场景和事件时间过滤。首轮保持检索实现不动，保留人物、场景、时间范围，不以提高命中率为目标；如果清洁事实仍频繁跨情境误用，再单独研究适用范围过滤。

### 5.5 占位符和支持标签有确定性的解析漏洞

| 数据集 | 含原样模板占位文本的 finding | good 标签情况 |
| --- | ---: | --- |
| E | 15/62 | 17 个 `SUPPORTED:`，2 个 `[SUPPORTED]:` |
| L | 24/210 | 47 个 `SUPPORTED:`，13 个 `[SUPPORTED]:`，其余含混合模板、UNSUPPORTED、方括号 UNCERTAIN |
| M | 136/1007 | 125 个 good 均为 `SUPPORTED:` |

占位统计逐条检查 evidence/lesson/pitfall 中已知 skeleton 文本，如 `[one short action or empty]`、`[short warning or empty]` 和未替换的支持标签模板。它不是英文方括号的一般统计。

当前 `_finding_is_reusable()` 只接受严格 `SUPPORTED:` 前缀，因而 E 的 2 条、L 的 13 条可能受纯格式影响被排除。但不能直接把这些全部补成可信成功，格式正确和证据充分仍是两件事。上述三组候选全部有非空建议，也说明空字段路径没有被有效使用。

### 5.6 学习对象与当前 Agent 已有漂移

三组 `evolution.log` 均记录源 SYSTEM_PROMPT 从 4315 字符变为当前 5948 字符。EgoLife 还记录 Agent 与三个视觉工具从 temperature=0.0 变为 1.0。训练源分别来自 8 月 31 日、9 月 3 日、9 月 2 日的历史运行。

旧轨迹中暴露的错误不一定仍是当前 Agent 的主要错误，新增经验也可能与当前系统提示重复。来源差异是已确认事实，收益影响是待验证假设。首轮必须固定源输入用于代码消融，最终确认再用当前基础 Agent 重采集训练轨迹，不能在同一比较中同时换轨迹、提示词和经验策略。

### 5.7 旧实验问题在本轮是否复现，以及是否一起修复

本节对照此前 EgoLife full 分析。旧样本和统计只作为历史线索，下面分别说明本轮实际出现在哪一层，避免把 finding 错误、最终经验错误、测试行为变化混为一谈。

| 历史问题 | V17 本轮证据 | 决策 |
| --- | --- | --- |
| 猜对被标成可信成功 | E 的 36、371 明确复现于 finding；L 的 1697 把出现在观众席泛化为获奖证据，并进入 Memory | 纳入 A/B/C，最高优先级；单列成功过程支持规则 |

| 要求搜索完整字幕 | 本轮最终 Skill 未发现相同指令；M 的 STG 有执行含义不清的 pixel-level extraction | 能力契约并入 B，不为旧全文字幕案例新增执行系统 |
| Skill ID 被当成工具名 | 本轮非法工具响应中未发现调用最终 Skill ID 或其哈希后缀；仍有其他拼错工具名 | 暂不修改推理展示和工具路由；保留历史回归线索 |
| agent summary 被当证据、无支持的提前停止 | 本轮最终 Skill 未发现旧的“overview 或 agent summary 确认即停止”；跨样本错误支持仍直接复现 | 证据来源与停止规则审核并入 A/B，不宣称旧停止技能导致了本轮退化 |
| finding 占位符、支持标签格式不一 | 三个数据集均有当前证据，详见 5.5 | 直接修复窄范围解析，随 A 完成 |
| GT 归因与摘要遗漏 | M 2165、E 366 有明确 GT 传播；摘要仍截断，原始训练轨迹未包含在副本中 | 答案隔离与源证据回查并入 A；不臆测哪些关键帧具体被遗漏 |
| 记忆检索到相似但不适用的事件 | E 406、L 3791/4178 有实际注入证据 | 首轮做 C 的事实与情境清理，结构化检索过滤留作独立下一步 |
| 拼接时间被当成自然时间 | E 366 有时间/选项混杂，但本轮未确认旧 359 的直接相减错误再次出现 | 时间语义约束及回归并入 C，不单独开发时间推理模块 |
| 生成完成就被视为有效进化 | 当前仍无实测效果接纳条件；本轮对照还暴露明显运行波动 | 执行第 8 节的独立验证，不在训练 Pipeline 内新增自动择优框架 |

**本轮“猜对”错误的直接证据。**

- E 的 `reflection/group_005.json`，样本 36：finding 自己引用 “Given the lack of evidence, I will select option D”，却仍以 `SUPPORTED:` 开头，并用与 ground truth 一致为理由。无需回看原始视频，也能确认这条 finding 的论证自相矛盾。
- E 的 `reflection/group_010.json`，样本 371：finding 明说 option mapping was a guess，却标成 SUPPORTED；lesson 甚至建议选择 ground truth if known，pitfall 要求答案匹配 ground truth。这同时暴露成功标签错误和答案污染。
- 36、371 本轮均未支持最终 Skill，也没有对应的最终 Memory。当前 TaskMaster 没有新增 Skill，不能沿用旧实验结论，声称这两条已经共同生成了本轮“靠背景猜答案”的技能。
- L 的 `reflection/group_037.json`，样本 1697：看到 Emma Stone 在观众席、错过颁奖画面，被解释为足以确认获奖者；同样的充分性断言进入最终 Memory。审核 `reflection/memories/audit/grounding_580a782deeb3edebcfa1cec6.json` 返回 OK。当前 finding 没有给出足以支持该通用规则的证据链，原始轨迹需要进一步回查；它也未在本轮六个 LVBench Memory 命中题的注入记录中出现，不能用它解释那些题的变化。

**本轮“未看见等于不存在”已经穿过整条训练链。**

- M 的 `reflection/group_190.json`，样本 2428：建议工具报告 insufficient evidence 时，转而 report the absence of the object。最终 Memory 原样保留该建议，审核 `grounding_a57e30f87320bcb4e7d9b9c3.json` 为 OK。
- M 的 `reflection/group_227.json`，样本 229：最终 Memory 的 pitfall 写出 assume absence only if the search budget is exhausted without finding the event。审核 `grounding_52a567d6277daae885d7c277.json` 为 OK。限制条件“预算耗尽”不能使这一推断成立。
- M 的 `reflection/group_145.json`，样本 1075：将 sampled frames 中没有相机调整证据，推广为 negative finding is a valid and supported conclusion。最终 Memory 保留，审核 `grounding_6f72b362a70d25e77bd7d03b.json` 为 OK。

这些错误不能只归因于提示词忘了写要求：当前生成提示和审核提示已有反对抽样未见推断不存在的内容，但同一 Reflector 仍放行。正则也不能覆盖所有同义改写。因此修复重点是让审核回查证据范围、区分观测与结论，并以实际违规案例检验约束，不再仅增加一段提醒。

**一起改机制，不一起扩展工程范围。** 把猜对、缺证据推断不存在、错误停止依据纳入现有 A/B/C 的证据和候选契约。Skill ID 隐藏、程序化 applies_when 路由、结构化人物/时间检索，都涉及推理侧行为，本轮没有足够新增证据支持同时实施。`applies_when` 当前只是随同类别 Skill 注入的文字条件，这一局限需要明确记录；B 先确保条件有意义且不互相冲突，不承诺已经实现条件自动筛选。

## 6. 最小代码改进方案

### A. 证据隔离与可回查的审核输入，最高优先级

**目标：经验只能从可定位的源证据形成，标准答案仅用于结果判定。**

主要改动位置：`videospy/evolving/offline_experience.py`、`reflector/base.py`、`reflector/offline_synthesis.py`。只调整离线路径，不修改在线反思。

1. 在离线 runner 明确分开分类 payload 与过程反思 payload。分类保留 prediction、ground_truth；过程 payload 用字段白名单，只保留问题、预测、任务类型、结果标签、执行指标、轨迹摘要。禁止通过完整 record、嵌套 metadata 或错误提示把 ground_truth 再带回去。问题中的未标注选项可以保留，它们是候选而非证据。
2. 从已读取的源轨迹构建一个局部 `evidence_by_sample` 映射，随本次 runner 传给现有审核。内容是有稳定编号的工具调用参数与原样 observation 文本、失败标记、实际执行预算和摘要省略信息。历史预算取源 run 配置，不能用当前预算倒推过去是否超限。保持原始工具输出的“未确认、推测、相互矛盾”等限定。助手总结单独标注为 self-report，不能充当事实依据。
3. 修改现有 `audit_memory()`、`audit_skills()` 的输入，加入所引用样本的源证据和当前工具能力约束。审核逐项检查候选的核心事实或完整规则，不再只检查 candidate 是否忠实复述 finding。不新增一轮全量 finding 审核，不换更大模型，不增加重试层。
4. 使用已有请求字符上限和分块函数。源文本按工具消息编号分块并明确省略范围，不让模型把“摘要没有”解释成“视频没有”。事实候选至少需要一段直接支持的 observation；涉及过程、顺序或停止策略的 Skill 还需要相关前后调用，不能把孤立观测当作完整策略支持。审核材料不够时拒绝该候选，不能默默把缺失证据当通过，也不默认把整段长视频重新送给模型。
5. 保存小型 `reflection/evidence.json` 旁路产物，记录源轨迹哈希、工具事件编号及审核所用文本片段。审核检查点的输入哈希包含实际证据与当前能力约束。沿用现有 finding、Skill、Memory 数据结构和 SQLite 表，不增加关系型来源系统。

为避免原样大文本重新成为巨型输入，首个实现只需要一个证据构建 helper 和明确的映射参数。必要时缩小一次审核所包含的支持样本数。单个样本仍超上限时留下 `insufficient_evidence` 诊断并不接纳相关候选；不因一个超长样本清空整个任务类型。

这里审核的仍是视觉工具模型输出的文本，不是真实世界的独立标注。它能纠正 finding 编造与错误传递，不能保证消除视觉模型自身的幻觉。不能把改动描述成已经获得绝对可靠的事实库。

**附带修复协议漏洞：**在 `offline_wire.findings_response()` 和 `normalize_offline_group()` 中，对已知 `SUPPORTED:` / `[SUPPORTED]:` 等等价形式做窄范围标准化；混合标签、缺失必填证据、未替换的 evidence 模板走现有纠错流程。可选 lesson/pitfall 的确切 skeleton 占位符转为空串并计数，不使用覆盖任意方括号的清洗规则。标准化后的标签仍须通过源证据审核，不能自动升级猜测。

**成功支持与结果正确分开：**保留 `outcome=good` 这个结果标签，但 `SUPPORTED` 必须表示源观察支持答案关键判断，且实际决策与该观察一致。36/371 这类明确猜测应为 UNSUPPORTED；摘要遗漏导致无法确认的应为 UNCERTAIN。只有“猜”这一字样不能机械决定状态，排除法若每步都有有效证据也可能成立。候选审核仍要检查原始支持，不能相信 finding 的前缀就跳过。预算耗尽时按任务要求提交最佳可用答案属于执行兜底，不因偶然答对而自动晋升成功 Skill。该约束复用现有标签和审核，不新增一套成功分数或另一轮全量 LLM 判定。

**验收：**2165 的标准答案坐标不能进入可见过程输入；366 的答案映射不能作为事实被接纳；源证据缺失、矛盾或仅有助手主张时不能产生已确认事实。既要拒绝错误案例，也要保留有原样工具观察支持的人名、时间、物体和事实，防止以空库冒充成功。

### B. Skill 只表达一个受支持、当前可执行的决策动作

**目标：每条规则有明确适用条件与一个决策机制，减少错误泛化及无收益搜索。**

主要改动位置：`reflector/offline_synthesis.py` 的 `SKILL_SPEC`、`SUPPORT_SPEC`、`skills()`、`audit_skills()`，以及 `offline_experience.normalize_offline_skills()`。

1. 保留至少两个独立 sample ID、相同 outcome/失败类型的现有约束，但审核必须要求每个样本支持同一个完整动作。需要不同子句分别由不同样本支持的候选直接拒绝，不在审核阶段再拼接或扩写。16/226、4454/4731 应成为机制不一致的回归案例。
2. 明确禁止改变题目目标限定，例如为方便识别而忽略“第二位、首次、最后、指定人物、指定时间”。清晰但不是目标的实例不能替代目标。由新问题和已见观察判断 applies_when，不允许写“Agent 答错”或裸的 failure/task 标签。
3. 对 `applies_when` 中完整匹配既有失败类型或纯任务名的条目做小型确定性检查，命中则让候选进入已有纠错/拒绝路径。不要增加覆盖全部自然语言的正则规则库。复杂的条件可观察性与行为合理性由现有源证据审核处理。
4. 要求新增工具调用说明尚未解决的答案关键差异，以及下一次调用要获取什么新证据；已有证据充分时直接完成答案。不能在预算耗尽后要求继续搜索，不能以多个同源工具一致作为事实充分性的通用标准。沿用当前预算，不另造数值预算。
5. 复用已有 `budget_aware` 提示片段中的适用内容，不再增加第二套预算策略。任务输出要求来自当前配置/问题中的正式要求，不能把选择题模板一概套到 MedVidBench 的坐标、评分和描述任务上。
6. 将已传入却未使用的 `current_skills` 放入 Skill 合成上下文，仅用来避免重复和冲突，不作为支持样本，不自动修改或删除人工技能。每种任务类型仍最多 3 条新 Skill，不提高容量、不改优化器算法。

候选允许包含一个有意义的继续/停止条件，不要求每条简单规则都套成长篇模板。比如“确认目标事件和顺序后核对选项是否反转顺序”可以保留；“多看一些直到找到答案”不能因为抽象而通过。

停止规则的支持必须包含证据出现与后续决策的顺序：摘要里声称已经确认不算独立证据；真正关键的证据来自后续 clip_skim/frame_inspect 时，不能倒推 overview 阶段就应该停止。历史 48/70 与 289/36 用作这一契约的回归线索，在获取原始轨迹后制作有来源标识的测试夹具，不把旧实验当成本轮实测。当前能力约束还应明确字幕究竟是全文还是采样窗口，不能从“存在字幕”推导出全文搜索能力。

**验收：**4454 不能学出忽略目标顺序；4731 不能给无关顺序策略凑支持数；M 的 DVC 预算失败案例不能被合成为无条件扩大搜索；裸 `fine_grained_inspection` 和 `reasoning` 不能作为 applies_when。正向测试保留同一可观察错误确实在两个样本出现的简短规则。

### C. Memory 只保留有范围的观测事实，去掉答题复盘

**目标：存入的内容能提供事件、对象或关系信息，而不是把答案标签和重复策略带进下一题。**

主要改动位置：`reflector/offline_synthesis.py` 的 `MEMORY_SPEC`、`MEMORY_AUDIT_SPEC`、`memories()`，离线 Memory 规范化与文本协议解析。

1. Memory 生成只要求自然问题式 context 和简短 evidence。程序补齐既有 lesson/pitfall 字段为空串，保持数据结构兼容。生成提示不再鼓励填建议；若兼容 JSON 路径仍返回非空建议，按契约纠错或拒绝，不能把有害建议悄悄删除后就认为整条记忆可信。
2. evidence 保留谁、做了什么、对象关系、在哪个场景及什么时间范围；只说“Agent 选错、步数耗尽、应更仔细看”不构成事实候选。没有有用事实时返回空集合，不补写常识或策略凑数量。
3. context 从该事实实际对应的问题生成，不能以任务标签或工具失败开头，不能列举多个无关问题吸引检索。保持程序可追踪的 source_sample_id，不把样本题号或正确选项写入可检索正文。
4. 复用 A 中的源证据审核，检查事实、情境、时间范围是否都被支持。具体名称和数字可以来自工具观察，但不能来自标准答案、未验证的选项或助手猜测。对 EgoLife 明确区分拼接视频秒数与 DAY/真实时钟，禁止仅靠拼接秒数计算自然日差或把“几小时前”脱离原查询时间保存。
5. 保持 embedding 模型、去重阈值 0.95、top_k=3、检索阈值 0.5 和推理注入代码不变。先通过正文变短、context 对准事实减少过程噪声，不同时改向量表示和检索算法，否则无法判断收益来自哪里。

**验收：**E 41 的 extensive search、M 2923 的执行复盘不再成为 Memory；2165 不能保留仅由答案提供的坐标；LVBench 4454 的 Gold(A)/Black(C) 答题映射不能入库。正向样本必须能保留观测到的具体事实，且仍可被相关自然问题检索。

事实化后仍可能出现 LVBench 跨情境误用。首轮只量化相关命中与无关命中，不降低阈值来追求覆盖。若这一风险仍占主导，下一轮再单独考虑源视频/场景和事件时间过滤，不为 V18 提前增加 schema、查询路由或通用记忆管理层。

**否定证据保留范围，不升级结论：**可以保存“所检查的指定帧/时间范围内未能确认目标”，前提是这条有限观察本身有用且范围清楚；不能改写为目标在整个视频不存在。预算耗尽只说明停止取证，不提供事件不存在的证据。2428/229/1075 作为直接反例，同时覆盖 evidence、context 和建议字段，防止清空 lesson/pitfall 后在事实正文继续保留相同错误。对任务正式允许的空结果不作一刀切禁止，但必须具有任务要求的证据与覆盖范围，不能仅用未检出或预算耗尽证明。

### D. 少量诊断与缓存依赖，随 A/B/C 完成

在现有 `cache_stats.json` 之外增加一个紧凑的 `quality_summary.json`，仅记录可以由流程准确计数的量：分类来源、有效/排除 finding、占位修复、支持不足/契约不符/证据不足的候选拒绝、最终 Skill/Memory 数量。记录候选 ID 与原因的旁路诊断，正常空结果与审核失败分开。

不增加数据库表，不把 raw_responses 数量当精确模型调用数，不保存密钥、完整请求配置或图像 base64。

更新现有阶段指纹的实际依赖：A 的输入与证据契约变化必须使 finding 及其下游失效；B 单独影响 Skill；C 单独影响 Memory；新的源证据审核输入进入相应 checkpoint 的 input_hash。分类和采样不变时可以复用。使用新运行目录，不能对已完成的 `offline_result.json` 直接 resume 来绕过新审核。

## 7. 实施顺序与代码范围

| 步骤 | 改动 | 需要重算 | 本步验证 |
| --- | --- | --- | --- |
| 0 | 固定源、manifest、模型服务与验证协议，补齐原始训练轨迹 | 无训练代码改动 | 能解释现有输入相同但输出不同的基线波动 |
| 1 | A：答案隔离、证据映射、现有审核回查、标签/占位处理 | finding 与两路下游 | 源证据边界回归、2165/366 等案例复核 |
| 2 | B：单机制 Skill、有效条件、预算与现有技能约束 | Skill 路径 | 固定第 1 步 finding/Memory 的单路消融 |
| 3 | C：事实型 Memory | Memory 路径 | 固定第 2 步 Skill 的单路消融 |
| 4 | 冻结候选，用当前基础 Agent 重采集训练源后确认 | 新源下完整训练 | 新源 V17 与新源 V18 比较，避免混淆源刷新与算法收益 |

步骤 1 是共同证据修复，影响两路，不能声称它是 Skill 或 Memory 单项优化。步骤 2、3 才可以分别归因。保留每步产物与代码提交，不引入组合爆炸的开关。未变化路径只在依赖指纹完全匹配时复用。

预计主要生产代码集中在 `offline_experience.py` 与 `reflector/{base,offline_wire,offline_synthesis}.py`。Pipeline 最多负责传递已有源信息，不改变版本提交事务。测试放入已有 `test_offline_experience.py`、`test_offline_continuous.py` 和必要的 `test_evolving.py`。不修改 `data/`、旧输出、在线流程、Agent 核心推理或 Memory 数据库 schema。

以下暂不实施：增大 group_size、增加 epochs、放宽支持数、提高经验容量、更换大模型、训练新 embedding、完整语义聚类、Skill 自动删除与全局重写、自动选择最优版本。全局 Skill fold 的顺序偏差和晚到样本覆盖早期候选是潜在问题，但本轮没有足够直接证据，应在修复可信度后再测。

MedVidBench 的通用 good/bad Judge 也有任务语义风险。先按 qa_type 抽查已有分类与正式评测的关系，记录客观分类和 LLM 分类的来源。若确认系统性错分，再单独改离线分类提示/适配，不立刻重写多任务 evaluator 或为 IoU、描述相似度随意设统一二值阈值。该变化会重算采样与全部下游，必须是独立实验。

## 8. 科研验证协议

### 8.1 将工程案例、开发集、冻结测试集分开

本文已查看的 V17 测试题是诊断集，不能再包装成 V18 的未见测试。上述具体样本可进入工程回归，但不得把测试题答案或其推理轨迹送入 Reflector 来生成技能和记忆。

正式 V18 在完整 train manifest 上先划分经验生成集和开发集，再分别取样，不能先按 lite 取样后再随意划验证题。开发集约 20%，比例和 seed 一次固定：

- EgoLife 按真实 query time 排序，较晚约 20% 作开发集，同一查询时刻一起划分。经验来源须早于被测查询，不能从拼接秒数自行推导真实日期。
- LVBench、MedVidBench 按源视频/案例分组划分，并检查任务类型覆盖，避免同一视频的近邻问题同时承担经验生成和独立验证。使用本地实际元数据映射，不能靠 sample ID 猜视频归属。
- 同一个开发集用于 V17/V18 对比，所有开发样本从分类、finding、支持审核、Memory 和跨目录缓存输入中排除。V17 对照也要在同一较小生成集重训，不能直接复用包含开发题的现有 V17 数据库。

类别太稀疏时明确报告样本数，不为凑齐类别反复换 seed。必要时扩大开发样本，而非在小类上宣布显著收益。

### 8.2 先控制比较条件，再执行固定消融

1. 记录并固定 Agent、三个视觉工具、Reflector、embedding 的模型和解码配置，以及源 run、manifest、代码、final 数据库的身份信息。三组旧源的提示漂移单独列出。
2. 首轮机制验证统一将 Agent 和三个视觉工具的 temperature 设为 0.0，固定 seed、并发和服务。只设置 CLI 的 Agent temperature 不够，必须检查工具子模型的合成配置。该配置覆盖适用于所有对照组，不将它算作 V18 收益。
3. 用相同配置的 Base 重复运行核对输出波动。temperature=0.0 仍非严格确定性保证。正式冻结比较使用事先固定的三组配对 seed，所有方案运行相同 seed 列表，不挑最好的一次；若需复现部署时 temperature=1.0，另作固定协议确认，不与 0.0 混算。
4. 先比较 Base、V17、A 在相同源和开发集上的 Skill/Memory/组合结果。A 的工程证据通过后，再测 A+B 和 A+B+C。未变化的组件在配置和产物相同的前提下复用；不要在每一步重跑同一组件后选择较高分。
5. 不在每题结果出现后手工删除导致 loss 的经验再反复测同一开发集。每次候选事先登记唯一变化与预期作用，开发集只用于有限阶段比较，最终候选冻结后在新保留测试集确认。

### 8.3 必须报告的指标

EgoLife/LVBench：总体与任务类型正确数、配对 win/loss、平均 Token/轮数、步数耗尽率、非法工具调用数量及涉及题数。LVBench 的类别有多标签，不能把类别分母相加当独立样本总数。

另按实际输入划分：新增 Skill 覆盖、Memory 命中、无 Memory、初始消息完全相同的样本。统计命中次数、不同记忆来源、正文长度，并抽查检索情境是否匹配。回答改善必须结合有无实际经验输入解释，不把 hits>0 当有效使用。

MedVidBench：分别报告官方各任务指标、成功/失败数、评分服务状态和成本，不合并成自造“总体准确率”。失败样本按固定计划分母报告，另给成功子集诊断，不能通过排除失败人为抬升效果。LLM 指标缺失时该指标的收益判定暂停。

跨 seed 报告均值和逐 seed 差值。配对不确定性按样本来源组估计，LVBench/MedVidBench 用视频为重采样单元，EgoLife 按可用的查询时间块分组；小样本时明确区间宽，不能仅凭净多一题宣称稳定提升。

### 8.4 接纳准则

工程门槛：已知答案泄漏、占位模板、无依据事实、错误目标替换、不可执行条件等回归通过；同时保留正向有效候选。全空 Skill/Memory 可以是一次有效拒绝结果，但属于“未学到可用经验”，不能算训练收益验收成功。

效果门槛事先固定，不采用旧草稿的“一次小验证集多一题且 Token 不增就自动发布”逻辑：

- 优先目标是相对同源 V17 和同配置 Base 的准确率/对应任务指标重复改善，Token 变化单独给出；有提升但成本增加时明确是质量与成本交换，不称无代价改善。
- 若主张效率收益，默认准确率/对应任务主指标不得下降，且 Token 在三个配对 seed 上均减少。不能用某次分数不降宣称已证明统计上的非劣；若研究另行允许非零容忍范围，必须在看结果前登记，不用运行后的波动解释任意下降。
- 不确定区间仍覆盖明显退化、主要收益来自未注入题或不同 seed 方向相反时，结论是证据不足，扩大预先保留的验证样本或如实停止，不能改写成功标准。
- 不要求每一个数据集、每一个组件都提升才记录研究进展，但单数据集收益不能写成跨基准稳定收益。组合效果必须独立测量。

最终由实验报告记录是否采用候选，不新增 Pipeline 内的自动 promotion、rollback 或 Base 选择逻辑。保持科研代码能够明确回答“改了哪个训练环节，输入是什么，学到什么，验证是否有效”。

## 9. 测试与交付检查

| 测试 | 正向与反向要求 |
| --- | --- |
| 答案隔离 | Judge 收到 reference；离线 finding/审核不收到 reference 字段或嵌套答案来源；问题中的未标注选项仍可用 |
| 证据审核 | 工具原样观察可支持事实；答案、助手总结、失败调用和缺失片段不能被当作已确认事实 |
| 成功过程支持 | E 36/371 不能因答对标可信成功；有证据的排除法不被误伤；执行兜底不自动成为成功 Skill |
| 否定与停止规则 | M 2428/229/1075 的未检出或耗尽推断不存在应拒绝；允许有范围的否定观察；后续证据不能支持提前停止 |
| 占位与标签 | 等价括号标签归一；混合模板不能升级成功；确切可选占位转空；普通正文不被误删 |
| Skill 支持 | 至少两例支持同一完整动作；不同机制、只支持其中一句、错认目标限定均拒绝 |
| 当前可执行性 | 纯失败标签条件、耗尽后继续调用、未提供的能力拒绝；合法简短条件保留 |
| Memory 事实 | 具体实体/时间且有工具依据可保留；答案映射、复盘建议、失去时间范围的事实拒绝 |
| 空结果与故障 | 正常无候选可完成；API/审核故障继续按现有失败机制保存断点，不伪装为空集合 |
| 缓存与隔离 | A/B/C 分别失效相应阶段；源证据或生成集改变不能误复用旧结果；旧 final 不原地修改 |
| 版本与预算 | 离线仍 initial→final 一次提交；超参数不变；无需新 SQLite schema |

实现时运行这些范围相关的现有测试及新增回归，不为文案或同义包装增加镜像测试。最后用小规模真实模型调用检查程序测试覆盖不到的语义质量，再开始正式开发集评测。
