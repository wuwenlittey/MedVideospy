# VideoSpy-RSI：证据诊断与成本反馈驱动的程序进化

日期：2026-10-02。状态：研究设计，尚未实现或运行新实验。

## 1. 研究问题与范围

从现有 VideoSpy 出发，在模型权重固定的条件下，让系统根据执行经验递归改进三个视觉工具、工具调用策略和证据组织方式，并在回答质量与完整任务 token 成本之间寻找更好的权衡。

研究假设：可靠、可组合的多粒度观察工具提供了有效的搜索起点；结合任务分组反思、必要的主动调查和实际执行反馈，能够比仅更新经验文本或无针对性的代码搜索，更有效地发现可迁移且成本合理的程序。

借鉴关系：

- VideoHarness-RSI：可执行候选、历史档案、当前最佳版本、完整执行评估与递归保留。
- Video-RSI：旧轨迹不足以明确失败原因时回看原视频，以及质量与观察成本的联合选择。
- VideoSpy：按任务类型分组反思、带引用的 Skill、事实与推理案例 Memory、证据审核、多粒度观察工具。

上述机制的组合与将帧数替换成 token，不能单独视为已确立的新颖贡献。候选贡献是：利用诊断和分阶段成本反馈，联合优化视频证据获取、证据表达及其后续使用；需要以实验验证相对近邻的额外价值。

## 2. 固定边界与可进化对象

每个版本 H 包含工具代码、控制策略、配置，以及与其兼容的 Skill 和 Memory 快照。固定模型、数据访问权限、评价器、计量器、答案协议和硬资源上限。不能通过修改评价器、漏记调用、读取测试标签或绕过数据边界获得收益。

第一版固定三个公开工具名称及必需参数、公共入口和轨迹记录契约；允许改变工具内部实现和调用它们的程序。新增复合操作先作为内部函数；公开新增工具接口作为后续实验。

| 对象 | 允许的修改 | 候选实例 |
|---|---|---|
| overview | 抽样分配、分辨率/拼图、查询与证据输出 | 保留全局时间覆盖，同时控制重复观察和描述长度 |
| clip_skim | 区间划分、采样密度、局部细化、查询与输出 | 长区间先定位候选事件，再仅细查不确定片段 |
| frame_inspect | 多时刻合并、分辨率策略、任务相关细节提取 | 将相关帧放入同一次比较，检验是否减少调用且保持识别能力 |
| 调用策略 | 首个工具选择、条件分支、调用顺序、继续/停止 | 明确时间地址直接定位；全局问题使用全局观察；细节未明确时升级检查 |
| 证据组织 | 去重、压缩、事实与解释分离、时间关联、复用 | 保存支持当前问题的事实、来源和未解决项，减少重复上下文 |
| Skill/Memory | 修改策略说明、适用条件、案例和引用 | 将验证过的操作保留为经验，并检查其与新工具行为是否冲突 |

进化应允许删除或绕过无用步骤，而不只是增加模块。已有基线已经具有部分相关策略；例如工具说明已经建议已知时间时直接定位。实际候选必须检查当前代码和执行轨迹，不能把已有能力重新命名为新增贡献。

## 3. 数据与版本

按视频划分三种用途：

1. 诊断集 D_diag：允许逐题反馈、轨迹分析、主动调查和局部调试。
2. 选择集 D_gate：候选完整执行、质量与成本比较。第一版仅向 proposer 提供聚合与预先定义的任务类别统计；不提供逐题标签或轨迹。
3. 测试集 D_test：最终冻结版本后使用，不参与选择或预算调整。

同一来源视频、多问题、跨日视频和流式任务按原有来源/时间约束处理。调查权限和所有新观察都必须有记录。诊断时允许看到训练标签，但视觉查询不得包含标准答案；候选触发条件必须来自部署时可见信息。

重复使用选择集仍可能造成适应性过拟合；聚合反馈不是独立性保证。固定搜索预算，最终以未参与搜索的视频和外部 benchmark 检查泛化。

每个候选保存 parent_id、代码与配置摘要、诊断证据、提案、完整评测结果、成本、保留/拒绝原因和兼容的经验快照。拒绝的版本也保留在档案中。修改工具返回格式后，审核依赖旧格式的 Skill；不能无声地继续注入已经失效的经验。

## 4. 每轮进化流程

### 4.1 当前版本执行并收集记录

运行当前已接受版本，产生真实的新轨迹。原始日志完整落盘，模型每次仅接收预算内相关内容。缓存和复用相同版本、相同配置的确定记录；工具或策略改变后，不把旧轨迹当成新版本的运行结果。

### 4.2 延续 VideoSpy 的分组反思，生成诊断报告

逐条评估结果与证据，按任务及疑似失败模式组织样本。保留三种重点案例：错误/证据不足、正确但昂贵、相似条件下正确且高效。

延续现有小组反思，但把本轮产生的 Skill 视为候选信息，先不直接覆盖已接受版本。报告应包含：问题模式、适用范围、支持与反例、涉及模块、尚未确定的原因、成本集中在哪些调用。

输入按 token 预算组装，而不仅按固定四条轨迹分组。携带必要的原始观察和索引，证据不足时按需读取相关完整记录。不要仅从逐题对错推导修改方案。

### 4.3 按需主动调查

仅当额外观察可能区分失败解释，或补救操作的收益不明确时调查。可使用原视频重看，也可从相同决策前缀比较不同操作：原策略、无新证据的重新推理、改变视觉查询、改变时间覆盖、相近预算的其他观察。

操作真实执行，后续轨迹重新生成。额外证据不得直接包含答案。诊断可以是多原因或未解决，不强迫将每次失败归为单一类别。

调查有单轮 token 上限，并记录实际费用。第一版可先实现定向补看；动作对照作为独立实验开关，用来测量比自由补看多出的价值。

### 4.4 成本感知的候选生成

Proposer 接收当前版本源码、分组诊断、相关轨迹、成本分解和历史尝试。每轮生成 1–2 个边界清楚的候选，优先修改一个主要机制及必要的依赖；同时容纳提高质量和降低冗余两类方向。

每个提案至少包含：

- 适用条件和支持样本；未确定的假设。
- 要修改的模块与实际代码行为。
- 预期改善什么证据缺口或成本来源。
- 哪些操作被减少，哪些调用/输出可能增加。
- 可能受损的任务类别，以及需要保留的成功行为。
- 原题、相似题和反例上的检查计划。
- 基于历史调用统计的成本预估区间；没有依据时标记未知。

输出是可执行候选版本，不只是建议。预估用于安排探索优先级，绝不代替实际计量。

### 4.5 分阶段验证

依次执行：接口和运行检查 → 诊断集相关案例与对照检查 → 选择集完整运行。局部修复失败的候选可在预算内调试；只有局部成功仍不够，完整运行才能反映增加某工具后是否减少了后续调用。

保留外部计量和评估边界。所有新工具内的模型调用仍须经过同一记录入口。异常、重试、未完成答案和缺失 usage 均记录，不删除困难问题以降低均值。

### 4.6 保留并递归

满足预先定义的质量—成本准则才接受候选；否则保留原版本。经验更新与代码更新一起版本化、一起评估。接受后，下一轮使用新程序重新收集诊断轨迹。

Skill 的语言审核是进入候选阶段的依据之一，不能代替候选执行验证。多个分别有效的改动如果要合并，应将合并版本作为新候选重新评估。

## 5. Token 成本的定义

推理成本以完整 QA 执行中所有模型调用为单位：

`C_infer(q,H) = sum(input_tokens(call) + output_tokens(call))`

包括主 Agent 的决策与最终回答、三个视觉工具内部调用，以及候选新增的辅助模型调用。每次请求重复携带历史观察时，其输入 token 都计入。提供方已经将视觉 token 计入输入总量时，不再重复加算帧数。

需要分开报告：

- 每题输入/输出 token、调用次数、均值和高分位数。
- 主 Agent 与各工具的分阶段成本；在 usage 支持时细分视觉/文本/缓存输入，无法细分时标记未知。
- 帧数、分辨率、采样覆盖和延迟等辅助指标，不能把帧数当作精确 token 成本。
- 离线成本：反思、调查、proposer、调试以及被接受和拒绝候选的评估总消耗。
- 如新增索引、预处理或跨题缓存，单独记录建库费用与实际复用次数。

总 token 是统一模型配置下的资源代理，不等于精确 FLOPs、延迟或费用。不同模型或输入/输出计价不同，需要额外报告分模型、分方向统计；第一版固定各角色的模型配置以便解释。

当前 metrics.py 已有任务内 usage 汇总；扩展重点是按调用阶段归因和数据完整性。`calls_without_usage` 不能按零消耗处理并用于宣称节省。存在缺失时需补足计量或将该候选的成本比较标记为无效。多线程新增调用也要验证计量上下文覆盖。

Proposer 应关注完整任务成本。缩短工具输出可能减少后续每轮重复输入；增加一次定位调用也可能减少多次盲目细查。两者均须实测。不能以删掉证据来源、降低答案完整性或无依据提前停止来追求 token 下降。

## 6. 候选选择

第一版不将准确率与 token 随意压成一个固定加权总分。定义每个 benchmark 的既定质量指标 Q，与完整 QA 平均成本 C，提前固定下列准则：

- 质量改善：Q 明确改善，C 的相对增长不超过 alpha。
- 效率改善：C 的相对下降至少 beta，Q 不低于允许的质量下界。

初始实验令允许质量退化量 epsilon=0，即不主动交换准确率换成本；如研究其他偏好，单独报告预先声明的设置。alpha、beta、噪声判定方法和任务类别底线在搜索前固定，不随某个候选事后调整。

如果允许 epsilon>0，同时相对固定初始/参考版本设置累计退化下界，避免每轮少降一点形成持续退化。任务类别底线仅在样本量和评价稳定性足够时使用；不能把细分小样本上的波动当作精确保证。

记录全部质量—成本点并保留非支配候选，用于展示不同预算的选择。递归仍以按既定规则选定的当前版本为主；第一版不扩展为复杂多分支种群搜索。

边界候选用配对结果和必要的复测检查随机性。开发集显著性不构成泛化保证；最终判断仍依赖未参与搜索的数据。复杂开放式任务采用已有固定评测器，避免同时更改 judge。

## 7. 一个候选示例

诊断：部分区间动作题先全局观察，再查看给定区间；完整执行还重复携带与该动作无关的长描述。需确认这些全局观察是否提供了必要的目标身份或上下文，不能只看调用次数就认定冗余。

候选：对能够从问题和既有证据明确确定目标及区间的样本直接局部观察；返回动作证据、实际时间来源和未解决项；需要全局上下文或目标身份不明时回到原有路径。

成本假设：减少全局视觉请求与后续重复输入，但可能因局部定位不准增加重试。预估基于实际历史调用统计，不虚构固定节省比例。

检查：相关失败题、原本正确的区间题、需要全局上下文的反例和混合选择集。只有完整执行显示收益才保留。此处仅作方案格式示例；VideoSpy 已有已知时间直接定位的工具说明，必须先确认真实轨迹中是否仍存在这类问题。

## 8. 最小实验

先在 LVBench 的合法视频互斥划分上建立可复现的小规模流程，再扩展 EgoLifeQA 与 MedVidBench。后者可能只有预抽帧，应保持相同数据可访问边界，不把不存在的原视频补看能力混入比较。

主要对照：

1. 原始 VideoSpy。
2. 现有普通进化（固定运行代码，提炼 Skill/Memory）。
3. 程序 RSI，仅依据旧轨迹，按质量筛选。
4. 程序 RSI，加主动调查，按质量筛选。
5. 完整方法：成本信息进入提案生成，并按质量与成本筛选。

关键消融将“提案是否看到成本”和“选择是否考虑成本”拆开，形成二乘二比较。另比较只改策略、允许改工具内部、联合修改，检验丰富底座的作用。每个对照匹配诊断数据、模型、工具访问权限和离线搜索预算；迭代次数相同不代表进化成本相同。

报告最终质量与成本、质量—成本曲线、到达目标质量的离线成本、候选接受率、各任务退化与收益、不同搜索运行的方差。展示代码和真实调用行为的改变，不以代码长度或工具数量衡量进化成功。

若部署使用同一成本单位，还可报告额外进化成本的回收规模：额外离线成本除以每题推理节省。不同模型的 raw token 不直接用于费用回收计算。

## 9. 实施顺序

1. 先补齐成本归因、版本快照和固定候选评价器。
2. 接入现有分组反思，形成候选诊断；允许修改工具内实现和策略，保留公共入口。
3. 接入代码 proposer、运行检查、选择集执行和档案。
4. 增加有预算的主动调查，按需加入同前缀动作对照。
5. 验证多轮递归和必要消融后，再研究新增公开工具或多分支档案搜索。

不需要一开始加入 LoRA、强化学习或无限制框架重写。先验证诊断、程序修改和成本反馈能否形成有效闭环。
